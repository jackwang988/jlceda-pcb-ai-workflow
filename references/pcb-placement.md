# PCB 布局：机械 BBox、朝向、Keepout 与可布线性

## 约束排序

原厂电气与 RF/高速设计依据、板框及装配安全、制板工艺 > 原生 DRC > 可布线性 > 鼠线长度 > 美观。P1 先选板厂工艺/NetClass/叠层和差分规则；P2 再布局；P3 布线；P4 DRC。不能等摆完器件才首次配置设计规则。

## 保护机械层，禁止无确认清板

- 对已有工程保存当前文件，记录板框、安装孔、挖槽、禁布区、机械定位、锁定对象；在另存工程/设计候选中操作。
- **不能默认 `pcb clear`。** `clearRouting()` 不是“清空所有器件和铜而完整保留机械图元”的安全事务。任意大范围删除必须有用户明确确认、受保护对象差异清单和回退方案。
- 任何自动调整后 save + 回读；失败不得无限循环移动器件。

## 实测几何与误报排除

- 通过 `pcb_Primitive.getPrimitivesBBox([id])` 逐图元读取真实 BBox；必要时另外读取庭院层、机械外形、焊盘以及 3D 装配体。不能把焊盘包围盒当 USB-C 插口机械方向。
- 实际板框可能是多边形，单纯 `board_bbox` 只能做粗筛；凹形、槽孔、非矩形板边和 3D 装配需额外证据或原生检查。
- 同面机械实体非法重叠应阻断；允许有证据的接口外伸，但必须另外检查焊盘是否在板内、配套结构与实际插拔空间。
- Keepout 对应各层及对象类型（铜皮、走线、过孔、器件等）逐项核对。不同层合法相交不应被误报；无法确定层信息必须 `NEEDS_EVIDENCE`。

## 条件性的 USB-C 与 ESP32 天线规则

- 只有实际存在 USB-C 母座才校验开口朝外：依据封装和外形，不由焊盘位置猜测；未有机械证据不得 PASS。
- 只有板载天线模组才校验天线端位置与射频净空：随模组移动/旋转同步修订 Keepout，参数以**具体型号原厂手册**为准。不得对所有 ESP32 一律设置 15mm。
- 无 USB/RF 的项目，不得因缺少这些专用对象而被阻断。可选 `data/profiles/esp32-board.json`。

## 指标与工具

- `short`、连接错误、线距/孔环/阻焊等由**原生 EDA DRC**负责。本 Skill 的 `scripts/geometry_audit.py` 只做额外的静态几何粗审。
- `overlap`、`off_board`、`keepout`、方向有证据才能判断；`nets/ratsnest/crossings/routability_score` 尚无可靠算法或完整 API 时记录 `NOT_MEASURED`，**绝不虚构评分**。
- G3 应给出实际审计证据与未解决机械风险。G4/G5 必须继续 DRC、Gerber/BOM/CPL 复核和用户确认。

证据契约见 `references/geometry-evidence.md`。该模块只读，不进行布线、自动移动、导出或下单。
