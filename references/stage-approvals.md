# 阶段确认（dialogue 模式）

本 skill 仅实现 `dialogue`（维护者 2026-10-30 决定）。`formal_engineering`（工程师本人填审批 JSON + packet_sha256 绑定）暂不做（设计上可扩展：由工程师本人填写审批 JSON，并以 packet_sha256 绑定当前版本）。

## 规则

- 每个门禁（G1–G5）由 Agent 汇报：**本次实际产出、未解决问题、风险、下一阶段依赖**，然后等用户**编号答复**。
- 用户在对话里确认 = 记录“用户已确认”，**不生成电子签名，也不当作技术通过**；专项检查（DRC、gerber_guard 等）照常执行。
- Agent 不得自动代答、不得把“继续”当作批准未呈现的风险。
- 修改后失效：确认只对当时呈现的版本有效，变更后须重新确认。

## 格式

```
【G3 布局确认】本次产出：模块分区图、间距报告、3 项例外
未解决：① 模组天线净空 12mm（项目目标 15mm）② U3 距板边 0.35mm（锣边 ≥0.2 满足；若用 V 割需 ≥0.4）
请回复：[1] 通过并进入布线  [2] 修改后重审（请写明改动）  [3] 暂停
```

## 各门禁的最低汇报内容

| 门禁 | 必须呈现 |
|---|---|
| G1 原理图 | ERC 结果、未连接引脚清单、电源/复位/时钟/接口逐项观察 |
| G2 库/封装 | 每个核心器件的引脚/封装对照 datasheet 结论、替代料说明 |
| G3 布局 | 分区、关键回路、天线/板边/孔位、已知例外 |
| G4 PCB | `drc_check` 结果、规则预设名、逐层读图观察 |
| G5 导出放行 | `gerber_guard` 全量输出（含“不评估”清单）、成本触发项、导出包 sha256 |
