# 原理图：拓扑优先、功能分区与真实几何（通用）

目标：形成参考样图所呈现的工整工程图——按功能分区，导线短而可追踪，模块标题清楚，标题栏独立保留。**仅参考布局风格；不复制图中的电路、数值、图样或 LOGO**。原理图电气设计仍以项目需求和元器件原厂手册为准。

## S2 绘制顺序

1. 先建立电源域、功能分组、原厂推荐连接与网络拓扑；记录不确定连接，不猜引脚定义。
2. 读取已选符号引脚方向、符号实际几何和标签占位。预先规划引脚 Stub、横纵走线通道与可用绘图区（扣除图框及标题栏）。
3. 依拓扑联合迭代功能模块位置、器件坐标/旋转、连接通道、旗标/网络端口及文字。**禁止先铺满器件，再事后挤压走线。**
4. 按模块内短线路和清晰跨模块信号连接落图；随后放置位号、参数、分区框、模块标题与注释。每批保存后回读。
5. 完成布局审计、页内及全工程 ERC；对照原厂手册确认电源、复位、时钟、USB 等高风险电路。

## 参考图的可复用版式

- 逻辑模块可以采用网格状分区，如“电源与 USB / 主控 / 串口下载 / 按键 / LED / IO”，**实际按项目功能域和页容量自适应**，不是固定八个框。
- 电源流向优先自上向下、信号流向优先自左向右；导线以正交水平/垂直为主。位号、数值、标题字号与旋转方向尽量统一。
- 标题栏、图框要单独规划禁入区域；同类模块留白均衡，但不可为了视觉居中破坏去耦、电源回路或其他电气约束。
- 先预估“器件 + Stub + 标签 + 端口 + 走线走廊”的页面空间；过载时按功能域分页。跨页用有明确网络语义的跨页连接方式，电源全局网络按项目规则统一管理。
- 不允许用颜色代替网络连通；5V/3V3/GND 等颜色只能作为可选视觉习惯，不能强加于所有电路。
- 不能把“5raw”当作间距单位，也不能把 5mil 作为所有项目唯一的原理图连接栅格。SCH API 1 单位 = 10mil，与 PCB API 的 1mil 不同。

## 碰撞与质量门槛

- `sch_Primitive.getPrimitivesBBox([id])` 需要按**单个图元**读取；集合调用只能得到集合总体 BBox，不能视为各器件尺寸。
- 原理图审计区分器件/标签/端口实体占位、Stub 通道、实际导线、分区框以及标题栏。合法导线端点接触、功能框包含内部器件不是非法碰撞。
- 真实实体侵入 Stub、标签与器件非法重叠、导线穿过非目标器件内部应报告冲突。异网交叉若未能确认连接语义仅预警，并以 ERC 判断。
- 使用 `scripts/geometry_audit.py --input schematic-evidence.json` 作**只读预审**，输入格式见 `references/geometry-evidence.md`；没有实测证据就输出 `NEEDS_EVIDENCE`。
- 页面质心及留白是建议性优化，不能替代电气拓扑及 ERC。

本规范是原理图规划与审计指导，不是“输入一句话自动求解全部图元位置”的完整自动布局器。
